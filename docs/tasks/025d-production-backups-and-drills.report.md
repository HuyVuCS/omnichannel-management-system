Database-password variant chosen: **the SCRAM-SHA-256 verifier is computed in PowerShell** (PBKDF2, 4096 iterations,
random 16-byte salt) and only `alter role … password '<verifier>'` is sent, as a statement file through the existing
`Invoke-StackSql` (superuser, local socket), after `set log_min_error_statement = panic; set
log_min_duration_statement = -1; set log_statement = 'none'`. The password never reaches PostgreSQL; nothing is piped
over stdin (Windows PowerShell 5.1 prepends a BOM there); the statement file is removed on both sides.

## Deviations from the task
1. **B and C not done — decision of the user at B1** ("no backup wanted any more"). Not a `Blocked` stop of mine:
   the user is the decider. Consequences are under "Blocked / questions".
2. **No `build` for the throwaway stacks** (the task's Part D says "build"). The image tags `omnichannel-api:local`,
   `-workers:local`, `-migrate:local` are shared by every compose project on the machine, production included: a
   rebuild without `GIT_COMMIT` would move the tags to images labelled `unknown`, and the next `up` of
   `omnichannel-prod` would recreate its containers from them. Nothing under `backend/`, `frontend/` or `docker/`
   changed since `264270c`, so the existing images are the current code; `up --no-build` used them.
3. The storage archive is counted with `docker exec` in a helper container that only waits (`sleep`), instead of a
   one-shot `tar` container: the count is taken after the storage service runs again, so the downtime did not grow
   (13.3 s against 14.4 s in 025b).
4. `rotate-secret.ps1` covers every row, not only the database rows: the drill may not put a value on a command line
   or in the chat, and "a new value in the file" needs a generator the user and Claude Code can both run. The webhook
   override file must be outside the repository (refused otherwise).
5. Runbook rows corrected by what the drill measured: `OMNI_MIGRATOR_PASSWORD` and `POSTGRES_PASSWORD` said "effect:
   none", but both variables belong to the `postgres` service, so `up` (or the next `run --rm migrate`) **recreates
   the database container** (seconds; API and Workers reconnected by themselves). The RabbitMQ row's `sh -c` no longer
   nests double quotes (they do not survive Windows PowerShell 5.1's argument passing; the values are letters and digits).
6. §13 has no destination type, task time, production backup size or production restore time: there are none.
7. `docs/implementation-log.md` not edited by me (Cowork's): the B1 decision is recorded here and in runbook §13.
